# Account Management System Test Plan

This plan describes the behavior implemented by the current COBOL application. Start each test in a fresh program run unless the pre-condition says to continue an existing run. The balance is held in working storage, starts at `$1,000.00`, and is not persisted between program runs. For cases marked as a stakeholder decision point, confirm the desired business rule before using it as a migration acceptance criterion.

|Test Case ID|Test Case Description|Pre-conditions|Test Steps|Expected Result|Actual Result|Status (Pass/Fail)|Comments|
|---|---|---|---|---|---|---|---|
|ACCT-001|Initialize a new account|Program is not running.|Start the application. Choose `1` to view the balance.|The displayed balance is `$1,000.00`.|||Confirms the initial value of `STORAGE-BALANCE`.|
|ACCT-002|View the current balance|Application is running with no prior transactions in this run.|Choose `1`.|The application displays the current balance, `$1,000.00`, and returns to the menu.|||Viewing the balance does not change it.|
|ACCT-003|Credit a positive amount|Application is running with balance `$1,000.00`.|Choose `2`; enter `250.00`; choose `1`.|The credit confirmation shows `$1,250.00`; the subsequent balance view also shows `$1,250.00`.|||Confirms the balance is written to shared in-memory storage and retained during the run.|
|ACCT-004|Credit a zero amount|Application is running with balance `$1,000.00`.|Choose `2`; enter `0.00`; choose `1`.|The application accepts the amount, reports `$1,000.00`, and the balance remains `$1,000.00`.|||Current implementation does not reject zero. Confirm whether zero-value credits should be allowed.|
|ACCT-005|Credit a negative amount|Application is running with balance `$1,000.00`.|Choose `2`; enter `-25.00`; choose `1`.|Verify and record how the COBOL runtime handles the signed input. The program has no explicit positive-amount validation; if accepted as negative, the arithmetic reduces the balance.|||Stakeholder decision point: should negative credits be rejected? Runtime/input behavior may affect the observed result.|
|ACCT-006|Debit a positive amount when funds are sufficient|Application is running with balance `$1,000.00`.|Choose `3`; enter `300.00`; choose `1`.|The debit confirmation shows `$700.00`; the subsequent balance view also shows `$700.00`.|||Confirms successful debit and stored balance update.|
|ACCT-007|Debit the exact available balance|Application is running with balance `$1,000.00`.|Choose `3`; enter `1,000.00`; choose `1`.|The debit succeeds and the displayed balance is `$0.00`.|||The current condition permits a debit when balance equals amount.|
|ACCT-008|Debit more than the available balance|Application is running with balance `$1,000.00`.|Choose `3`; enter `1,000.01`; choose `1`.|The application displays the insufficient-funds message; the balance remains `$1,000.00`.|||Confirms no write occurs on the insufficient-funds path.|
|ACCT-009|Debit a zero amount|Application is running with balance `$1,000.00`.|Choose `3`; enter `0.00`; choose `1`.|The debit is accepted, reports `$1,000.00`, and the balance remains `$1,000.00`.|||Current implementation has no explicit zero-amount validation. Confirm desired policy.|
|ACCT-010|Debit a negative amount|Application is running with balance `$1,000.00`.|Choose `3`; enter `-25.00`; choose `1`.|Verify and record how the COBOL runtime handles the signed input. The code has no explicit positive-amount validation; if accepted as negative, subtracting it increases the balance.|||Stakeholder decision point: should negative debits be rejected? Runtime/input behavior may affect the observed result.|
|ACCT-011|Retain balance across multiple operations|Application is running with balance `$1,000.00`.|Credit `100.00`; debit `40.00`; choose `1`.|The final balance displayed is `$1,060.00`.|||Confirms operations read the latest stored value, not just the initial value.|
|ACCT-012|Reset balance after restarting the application|In a first run, credit `100.00` and confirm the balance is `$1,100.00`; exit normally.|Start a new application run and choose `1`.|The displayed balance is `$1,000.00`.|||Confirms the current implementation does not persist balance between runs. Stakeholders should confirm this is intended.|
|ACCT-013|Reject a menu choice below the valid range|Application is running.|Enter `0` at the menu.|The invalid-choice message is displayed and the menu is shown again; the account balance is unchanged.|||`USER-CHOICE` is a single-digit field; use numeric out-of-range values for this case.|
|ACCT-014|Reject a menu choice above the valid range|Application is running.|Enter `5` at the menu.|The invalid-choice message is displayed and the menu is shown again; the account balance is unchanged.|||`USER-CHOICE` is a single-digit field; use numeric out-of-range values for this case.|
|ACCT-015|Exit the application|Application is running.|Enter `4` at the menu.|The menu loop ends and the application displays the goodbye message.|||Confirms normal termination.|
|ACCT-016|Credit at the balance field's maximum capacity|Application is running with balance `$1,000.00`.|Choose `2`; enter `998,999.99` (or `998999.99` if commas are not accepted); inspect the confirmation and then view the balance.|The representable maximum is `$999,999.99` (`PIC 9(6)V99`). Record whether the operation reaches that value correctly.|||Boundary test for the COBOL numeric field; exact input formatting depends on the runtime.|
|ACCT-017|Credit beyond the balance field's capacity|Application is running with balance `$1,000.00`.|Choose `2`; enter an amount that would make the balance exceed `$999,999.99`; inspect the output and then view the balance.|No overflow policy is implemented explicitly. Record observed runtime behavior and agree the desired business result, such as rejecting the transaction without changing the balance.|||Stakeholder decision point and migration requirement: define behavior for values outside `PIC 9(6)V99`.|
|ACCT-018|Confirm account scope is a single account|Application is running.|Credit `75.00`; view the balance; exit and start a new run; view the balance again.|In the first run, the balance is `$1,075.00`; after restart, it is `$1,000.00`. The application has no student identity or multiple-account selection.|||Confirms the implemented scope and in-memory lifecycle; validate against intended product requirements.|
